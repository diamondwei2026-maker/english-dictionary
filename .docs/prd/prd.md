## 2. 产品概述与背景

### 2.1 产品定位

面向中文母语者的认知语言学英语词典 APP。以**物理意象（Physical Image）**为切入点，帮助用户从最原初的物理感知理解英语词汇，再沿着逻辑演化路径掌握引申义，而非死记硬背中文翻译。

### 2.2 业务背景

传统英汉词典的问题是：用户看到中文翻译（如 `grasp = 理解`），却不知道这个词和"抓住"之间的关联，导致记忆碎片化、无法灵活运用。本产品引入认知语言学方法——每个单词关联一张物理意象 SVG 图示（如"液体沿阻力最小路径流动"→ flow），展示词义从物理感知到抽象引申的完整演化链。

### 2.3 产品目标

- 建立以物理意象为核心的词典产品心智，差异化传统英汉词典
- 支持按词库维度组织词汇（基础高频 / 商务 / 学术 / 动词专项等）
- 提供管理后台，使内容运营人员可自助维护词库和词条
- 为后续引入 AI 自动生成词条铺好产品框架（管理后台已预留 AI 生成能力）

### 2.4 核心价值主张

**不是查翻译，而是建立语感锚点**——每个单词回到最原始的物理意象，像母语者一样从感知出发理解词汇。

## 3. 目标用户画像

### 3.1 用户角色概览

| 角色 | 描述 | 核心诉求 |
|------|------|---------|
| 普通用户 | 中文母语英语学习者，有一定基础（高中以上），希望突破"中式英语"思维 | 查词时看到词义来源，理解引申逻辑，积累搭配 |
| 管理员 | 词典内容运营人员，负责维护词库和词条内容 | 高效增删改查词库/词条，支持 AI 辅助生成内容 |

### 3.2 各角色详细画像

**普通用户**

- 使用场景：利用碎片时间每日学 3-5 个单词；遇到生词随时搜索；按词库系统学习某一类词汇
- 典型行为：打开 APP 浏览「今日一词」→ 查看词义演化链条 → 学习引申义 → 记忆搭配
- 痛点：现有词典只给中文翻译，缺乏系统性词义理解，记了就忘
- 期望：看到一个词的"为什么"，理解词义演化的逻辑链

**管理员**

- 使用场景：日常维护词库内容，新增/编辑/删除词库和词条；使用 AI 辅助生成词条初稿后人工润色
- 典型行为：在后台概览查看数据总量 → 进入词库/单词管理 → 新增或编辑条目 → AI 填充基础内容 → 人工修正后发布
- 痛点：手工编排认知语言学词条工作量巨大，需要 AI 辅助提效
- 期望：AI 一键生成词条的物理意象、引申义链、例句和搭配

## 4. 用户故事与场景

### 4.1 核心用户旅程

#### 旅程 1：普通用户每日学词

- **用户目标**：今日花 5 分钟学习一个单词的完整认知
- **前置条件**：用户已登录
- **操作步骤**：
  1. 打开 APP，首页展示「今日一词」（蓝色渐变卡片，含物理意象描述）
  2. 点击进入单词详情页 → 看到物理意象 SVG 图示
  3. 阅读「核心义」+ 例句（中英对照）
  4. 逐条下滑阅读「引申义演化」：逻辑演化描述 → 引申义 → 词性 → 例句
  5. 底部查看「常见搭配」，建立语感
- **预期结果**：用户完成了对一个单词从物理感知到抽象引申的完整学习
- **异常分支**：单词不存在 → 提示"单词不存在"，引导返回首页

#### 旅程 2：搜索并学习特定单词

- **用户目标**：在阅读或工作中遇到一个生词，搜索并理解它
- **前置条件**：无
- **操作步骤**：
  1. 在首页搜索框输入英文单词
  2. 搜索结果实时过滤显示匹配的单词列表（按单词名/核心义匹配）
  3. 点击单词进入详情页，按旅程 1 流程学习
- **预期结果**：快速找到目标单词并完成学习
- **异常分支**：无匹配结果 → 提示"未找到相关单词"，引导去管理后台添加

#### 旅程 3：管理员维护词库

- **用户目标**：为 APP 新增一个词库并添加若干词条
- **前置条件**：管理员已登录
- **操作步骤**：
  1. 进入个人中心 → 点击「管理后台」→ 进入数据概览页
  2. 进入「词库管理」→ 点击新增 → 填写名称和描述 → 保存
  3. 进入「单词管理」→ 点击新增 → 输入单词名 → 点击「AI 自动生成词条」
  4. AI 填充音标、核心义、物理意象类型、例句、引申义链、搭配
  5. 管理员人工校验/修改各项内容 → 保存
- **预期结果**：新词库和词条成功创建，在前端搜索可查
- **异常分支**：AI 生成超时 → 显示加载动画后自动完成（模拟场景中延迟 1.8s）

### 5.2 各功能详细说明

#### F-01：首页搜索与词表

- **优先级**：P0
- **功能描述**：提供搜索框输入英文单词进行实时过滤；无搜索内容时展示全部词汇列表
- **前置条件**：无
- **主要流程**：
  1. 用户在搜索框输入文字
  2. 系统实时匹配单词名（大小写不敏感）和核心义描述
  3. 结果以列表展示：单词名 + 音标 + 核心义截断预览 + 所属词库标签
  4. 无匹配时显示空状态文案
- **异常处理**：搜索无结果 → 提示"未找到相关单词，可在管理后台添加新词汇"
- **关联功能**：F-03 单词详情页（点击搜索结果跳转）

#### F-02：今日一词

- **优先级**：P1
- **功能描述**：首页顶部以醒目蓝色渐变卡片每日推荐一个单词
- **前置条件**：无
- **主要流程**：
  1. 按当天日期取模 mockWords 数组，确定今日单词
  2. 卡片展示：标签"核心物理意象" + 单词名 + 音标 + 核心义描述
  3. 点击进入该单词详情页
- **异常处理**：无
- **关联功能**：F-03 单词详情页

#### F-03：单词详情页

- **优先级**：P0
- **功能描述**：展示一个单词的完整认知语言学信息
- **前置条件**：从搜索/词表/今日一词/词库详情点击进入，携带 wordId
- **主要流程**：
  1. 顶部 sticky 栏：返回按钮 + 所属词库标签
  2. 单词大头：单词名（超大字号）+ 音标
  3. 物理意象区域：对应类型的 SVG 图示（如 flow→流速剖面图，grasp→多点包围施压图，break→应力断裂图 等 8 种）
  4. 核心义：核心义描述 + 中英对照例句（左侧蓝色边框高亮）
  5. 引申义演化：每个引申义独立卡片，包含 逻辑演化描述 → 箭头 → 引申义 + 词性标签 → 例句（左侧绿色边框高亮）
  6. 常见搭配：以 tag 形式横向排列
- **异常处理**：wordId 无效 → 提示"单词不存在"，提供返回首页按钮
- **关联功能**：依赖 F-01、F-02、F-04；F-07 管理后台维护数据

#### F-04：词库浏览

- **优先级**：P1
- **功能描述**：展示所有词库列表 + 各词库下的词汇
- **前置条件**：无
- **主要流程**：
  1. 词库列表页：每张卡片含词库名称、描述、收录单词数、渐变色背景
  2. 点击某词库进入词库详情 → 展示该词库下的所有单词列表
  3. 词库详情页顶部有返回按钮，可回到词库列表
  4. 空词库显示空状态
- **异常处理**：词库无单词 → 显示"该词库暂无单词"
- **关联功能**：F-03 单词详情页

#### F-05：用户认证

- **优先级**：P0
- **功能描述**：手机号 + 密码的登录和注册功能
- **前置条件**：无
- **主要流程**：
  1. 个人中心未登录态 → 点击「登录」或「注册」进入认证页
  2. 认证页顶部可切换登录/注册 Tab
  3. 登录：输入手机号 + 密码 → 验证 → 管理员自动跳转管理后台，普通用户跳转个人中心
  4. 注册：输入用户名 + 手机号 + 密码 → 创建账号 → 自动登录
  5. 支持 Enter 键提交
- **异常处理**：
  - 手机号格式不合法（非 1[3-9]xxx）→ 提示"请输入有效的手机号"
  - 密码错误 → 提示"手机号或密码不正确"
  - 字段为空 → 提示"请填写所有必填字段"
  - 注册用户名未填 → 提示"请填写用户名"
- **关联功能**：F-06 个人中心、F-07 管理后台（权限判断）
- **业务规则**：
  - 密码经 bcrypt 加密存储，JWT Token 2h 有效期
  - 管理员识别依据 JWT payload 中 `role === 'admin'`
  - 注册/登录均需手机号格式校验（前后端双重校验）

#### F-06：个人中心

- **优先级**：P1
- **功能描述**：展示用户信息和功能入口
- **前置条件**：无（未登录展示引导登录 UI）
- **主要流程**：
  - **未登录态**：显示头像占位 + "登录后开始学习"引导文案 + 登录/注册按钮
  - **已登录态（普通用户）**：用户信息卡片（渐变背景、用户名、手机号、角色标签）+ 学习统计卡片（已学单词数、今日目标进度）
  - **已登录态（管理员）**：用户信息卡片（紫色渐变背景区别于普通用户的蓝色）+ 管理后台入口按钮
  - 共同项：设置入口（当前仅占位）+ 退出登录按钮
- **异常处理**：无
- **关联功能**：F-05 用户认证、F-07 管理后台

#### F-07：管理后台

- **优先级**：P0（内容管理不可或缺）
- **功能描述**：管理员对词库、单词、用户数据进行管理
- **前置条件**：管理员登录
- **主要流程**：
  
  **a) 数据概览**
  - 顶部统计条（蓝色渐变）：词库数 / 单词数 / 用户数
  - 三个功能入口卡片：词库管理 / 单词管理 / 用户管理
  - 「退出管理」按钮返回个人中心

  **b) 词库管理**
  - 列表页：每个词库卡片显示名称、描述、收录单词数、编辑/删除按钮
  - 新增/编辑表单：词库名称 + 词库描述
  - 删除需 confirm 确认

  **c) 单词管理**
  - 列表页：搜索框 + 单词卡片列表（单词名、音标、核心义截断、所属词库标签、引申义数量）
  - 新增/编辑表单（核心功能）：
    - **AI 生成区域**：输入单词 → 点击「AI 自动生成词条」→ 1.8s 模拟生成 → 自动填充所有字段
    - **基本信息**：所属词库下拉、音标
    - **核心义**：核心义描述 + 英文例句 + 中文翻译
    - **物理意象图**：当前图示预览 + 「重新生成」按钮切换 8 种图示类型
    - **引申义列表**：多个引申义卡片，每个含 逻辑演化描述 + 引申义 + 词性下拉 + 例句 + 翻译；支持添加/删除引申义
    - **常见搭配**：输入框，以中文逗号/顿号/英文逗号分隔
    - 保存按钮

  **d) 用户管理**
  - 列表页：用户卡片（头像首字母 + 用户名 + 角色标签 + 手机号 + 已学单词数）
  - 当前仅查看，无编辑/删除

- **异常处理**：
  - 词库删除需二次确认 → confirm 弹窗
  - 单词删除需二次确认 → confirm 弹窗
  - 新增时未填单词名或未选词库 → 保存按钮禁用
- **关联功能**：F-05（权限判断）、F-01/F-02/F-03/F-04（前端展示的数据来源）

#### F-08：底部导航

- **优先级**：P0
- **功能描述**：全局底部固定导航栏，三个 Tab
- **前置条件**：非管理后台页面
- **主要流程**：
  - 三个 Tab：搜索（首页）/ 词库 / 我的
  - 当前页面高亮蓝色，非当前页面灰色
  - 管理后台全屏，隐藏底部导航
- **异常处理**：无
- **关联功能**：全局页面路由

## 6. 业务规则与逻辑边界

### 6.1 核心业务规则

| 规则编号 | 规则描述 | 触发条件 | 规则逻辑 |
|---------|---------|---------|---------|
| BR-01 | 手机号校验 | 登录/注册提交 | 手机号去除空格后匹配正则 `^1[3-9]\d{9}$` |
| BR-02 | 角色跳转 | 登录成功后 | role=admin → 跳转管理后台；role=user → 跳转个人中心 |
| BR-03 | 今日一词算法 | 首页加载 | 取 `mockWords[Math.floor(Date.now() / 86400000) % mockWords.length]`，基于 UTC 天数取模 |
| BR-04 | 搜索匹配 | 用户输入搜索词 | 匹配 `word.word`（大小写不敏感）OR `word.coreMeaning` 包含搜索词 |
| BR-05 | AI 生成规则 | 管理后台点击 AI 生成 | 调用 DeepSeek API 生成词条 JSON；相同单词 24h 内走 LRU 缓存不重复调用；支持 SSE 流式响应 |
| BR-06 | 物理意象类型 | 编辑单词时选择 | 8 种：flow/grasp/break/bear/drive/light/leverage/yield，每种对应一个独有 SVG |
| BR-07 | 管理后台权限 | 访问管理后台 | 仅 role=admin 可见管理后台入口；后端 API 通过 adminMiddleware 鉴权，非 admin 返回 403 |
| BR-08 | 密码安全 | 登录/注册 | 密码经 bcrypt（10 rounds）加密存储；JWT Token 2h 有效期 |

### 6.2 状态流转

#### 用户认证状态

```
未登录 → (登录成功) → 已登录(普通用户)
未登录 → (登录成功, role=admin) → 已登录(管理员)
已登录 → (退出登录) → 未登录
```

#### 视图路由状态（ViewState）

```
home ──→ wordDetail ──→ home
home ──→ libraries ──→ libraryWords ──→ wordDetail ──→ home
profile ──→ login ──→ profile
profile ──→ register ──→ profile
profile ──→ admin (role=admin) ──→ adminWordEdit(预留) ──→ admin
admin ──→ profile (退出管理)
```

### 6.3 边界条件与约束

- **数据持久化**：所有数据存储在 MongoDB Atlas，通过 REST API 读写，刷新/重启不丢失
- **设备适配**：最大宽度 430px，居中显示，移动端 H5 优先
- **管理后台与前端分离**：管理后台全屏覆盖，不显示底部导航，通过 JWT Token 角色鉴权
- **并发处理**：MongoDB 文档级原子操作；收藏/取消收藏幂等设计

## 8. 非功能需求

### 8.1 性能体验

- 搜索支持防抖（前端 300ms）+ 后端正则索引匹配，分页 20 条/页
- 物理意象 SVG 为内联 inline SVG，无额外网络请求
- AI 词条生成：首次调用 DeepSeek API（~3-5s），缓存命中 < 50ms
- SSE 流式响应：AI 生成结果逐字段推送，用户可实时看到内容

### 8.2 安全与合规

- 密码加密存储：bcrypt + salt（10 rounds）
- 认证：JWT Bearer Token（2h 有效期）
- API 鉴权：adminMiddleware 校验管理员角色
- 请求限流：登录 15min/10 次，AI 生成按用户 1min/10 次
- HTTP 安全头：Helmet（CSP、HSTS、X-Frame-Options 等）
- CORS：生产环境白名单限制 Vercel 域名
- 手机号格式校验：`^1[3-9]\d{9}$`（前后端双重校验）

### 8.3 兼容性与集成

- 目标平台：移动端浏览器（iOS Safari、Android Chrome），桌面端兼容但非主要场景
- 无外部系统集成需求（当前版本）
- 后续需集成后端 API + 真实 AI 词条生成服务

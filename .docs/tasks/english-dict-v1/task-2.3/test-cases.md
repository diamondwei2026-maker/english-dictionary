# 测试用例 — Task 2.3: 前端认证集成

## 测试范围说明

本 Task 涉及前端认证逻辑从 mock 替换为真实后端 API 调用。测试覆盖以下维度：
- **API 请求模块**：封装是否统一处理 Token、错误、双端适配
- **登录/注册页面**：表单交互、API 调用、成功/失败处理
- **登录状态管理**：Token 持久化、全局状态、退出登录
- **路由守卫**：401 自动跳转、登录后跳转

后端 API 契约（已由 Task 2.1/2.2 实现）：
- `POST /api/auth/register` — body: `{ phone, password, username? }` → 201
- `POST /api/auth/login` — body: `{ phone, password }` → 200 + `{ token }`
- 认证 Header: `Authorization: Bearer <token>`
- 错误格式: `{ error: { code, message, errors? } }`

## TC-001: 登录 — 正常流程，使用正确凭证

- **类型**: 功能测试
- **关联验收标准**: 登录/注册页面改为调用真实 API
- **前置条件**:
  - 后端服务运行中
  - 已注册用户：手机号 `13800000001`，密码 `a123456`
  - localStorage 中无残留 Token
- **输入**:
  - 手机号：`13800000001`
  - 密码：`a123456`
- **执行步骤**:
  1. 打开认证页面（`/pages/auth/index?mode=login`）
  2. 在手机号输入框输入 `13800000001`
  3. 在密码输入框输入 `a123456`
  4. 点击"登录"按钮
  5. 观察页面行为和网络请求
- **预期输出**:
  - 发起 `POST /api/auth/login` 请求，body 为 `{ phone: "13800000001", password: "a123456" }`
  - 响应状态码 200，响应体包含 `id`、`phone`、`username`、`role`、`token` 字段
  - `token` 存入 localStorage（key 如 `token` 或 `auth_token`）
  - 用户信息存入全局状态（`setGlobalUser` 或等效方法）
  - 显示 Toast "登录成功"
  - 普通用户跳转至 `/pages/profile/index`；管理员跳转至 `/pages/admin/index`
- **清理**: 清除 localStorage 中的 Token

## TC-011: API 请求模块 — 401 响应自动处理

- **类型**: 功能测试
- **关联验收标准**: 401 响应自动清除 Token 并跳转登录页
- **前置条件**:
  - localStorage 中存有过期或伪造的 Token
- **输入**: 发起一个需要认证的 API 请求
- **执行步骤**:
  1. 手动在 localStorage 中设置一个过期/伪造的 token
  2. 刷新页面或访问需要认证的页面
  3. 观察请求响应和页面行为
- **预期输出**:
  - 发起请求，Header 携带伪造 Token
  - 后端返回 401（`TOKEN_EXPIRED` 或 `INVALID_TOKEN`）
  - API 模块拦截 401 响应
  - 自动清除 localStorage 中的 Token
  - 自动清除全局用户状态
  - 跳转至登录页（`/pages/auth/index?mode=login`）
- **清理**: 确保 localStorage 无残留

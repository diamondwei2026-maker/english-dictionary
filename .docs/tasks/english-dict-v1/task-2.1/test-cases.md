> 生成日期：2026-07-08 | 关联 Task：[task.md](./task.md)

## 测试范围说明

本任务实现 `POST /api/auth/register` 和 `POST /api/auth/login` 两个端点。测试覆盖注册、登录、输入验证、错误处理四大方向。

---

## A. 注册接口 (`POST /api/auth/register`)

### TC-A01: 正常注册 — 提供所有必填字段
- **类型**: 功能测试
- **关联验收标准**: `POST /api/auth/register` — 接收 phone、password、nickname，创建用户
- **前置条件**: 数据库中不存在 `phone=13800138001` 的用户
- **输入**:
  ```json
  { "phone": "13800138001", "password": "abc123", "nickname": "测试用户" }
  ```
- **执行步骤**:
  1. 发送 `POST /api/v1/auth/register` 请求，body 含 phone、password、nickname
  2. 检查响应
  3. 在 MongoDB 中查询 `users` collection
- **预期输出**:
  - HTTP 状态码：201
  - 响应体包含 `id`、`phone: "13800138001"`、`nickname: "测试用户"`
  - 响应体**不包含** `passwordHash` 字段
  - 数据库中 `passwordHash` 为 bcrypt 哈希值（以 `$2b$` 开头），非明文
- **清理**: 删除该用户

### TC-A02: 注册时 nickname 缺失 — 使用手机号脱敏作为默认昵称
- **类型**: 功能测试 / 边界测试
- **关联验收标准**: nickname 可选，默认用手机号脱敏
- **前置条件**: 数据库中不存在 `phone=13800138002` 的用户
- **输入**:
  ```json
  { "phone": "13800138002", "password": "Test@1234" }
  ```
- **执行步骤**:
  1. 发送 `POST /api/v1/auth/register` 请求，body **不含** `nickname`
  2. 检查响应和数据库
- **预期输出**:
  - HTTP 状态码：201
  - 响应体中 `nickname` 为手机号脱敏格式（如 `138****8002` 或等效默认值）
  - 数据库中 `nickname` 有默认值且不为空
- **清理**: 删除该用户

### TC-A03: 重复手机号注册 — 返回 409 Conflict
- **类型**: 异常测试
- **关联验收标准**: 手机号唯一性检查（重复注册返回明确错误）
- **前置条件**: 已有一个 `phone=13800138003` 的用户（先注册一次）
- **输入**:
  ```json
  { "phone": "13800138003", "password": "SomePwd1" }
  ```
- **执行步骤**:
  1. 第一次注册 `phone=13800138003`，成功
  2. 第二次使用相同 phone 再次注册
- **预期输出**:
  - 第一次：201 Created
  - 第二次：409 Conflict
  - 错误响应体包含 `error.code`（如 `PHONE_EXISTS`）和中文/英文提示信息
- **清理**: 删除该用户

### TC-A04: 手机号格式错误 — 非 11 位

## B. 登录接口 (`POST /api/auth/login`)

### TC-B01: 正常登录 — 返回用户信息
- **类型**: 功能测试
- **关联验收标准**: `POST /api/auth/login` — 验证后返回用户信息
- **前置条件**: 已注册用户 `phone=13800138010, password=Test@5678`
- **输入**:
  ```json
  { "phone": "13800138010", "password": "Test@5678" }
  ```
- **执行步骤**:
  1. 先注册该用户（通过 API 或 Seed）
  2. 发送 `POST /api/v1/auth/login` 请求
  3. 检查响应
- **预期输出**:
  - HTTP 状态码：200
  - 响应体包含：`id`、`phone: "13800138010"`、`nickname`
  - 响应体包含 `token` 字段（占位或 JWT 字符串）
  - 响应体**不包含** `passwordHash`
- **清理**: 删除该用户

### TC-B02: 手机号不存在 — 返回 401（不暴露用户存在性）
- **类型**: 异常测试
- **关联验收标准**: 手机号不存在返回 401（不区分"用户不存在"和"密码错误"）
- **前置条件**: 数据库中无 `phone=13900000000` 的用户
- **输入**:
  ```json
  { "phone": "13900000000", "password": "abc123456" }
  ```
- **执行步骤**:
  1. 发送 `POST /api/v1/auth/login` 请求，使用不存在的手机号
- **预期输出**:
  - HTTP 状态码：401
  - 错误信息为统一措辞（如 "手机号或密码错误"），**不应**透露 "用户不存在"
- **清理**: 无

### TC-B03: 密码错误 — 返回 401（不区分错误类型）
- **类型**: 异常测试
- **关联验收标准**: bcrypt.compare 验证密码；不区分"用户不存在"和"密码错误"
- **前置条件**: 已注册用户 `phone=13800138011, password=Correct1`
- **输入**:
  ```json
  { "phone": "13800138011", "password": "WrongPassword1" }
  ```
- **执行步骤**:
  1. 确保用户已存在
  2. 发送登录请求，使用错误的密码
- **预期输出**:
  - HTTP 状态码：401
  - 错误信息与 TC-B02（用户不存在）**完全相同**（防撞库枚举）
- **清理**: 删除该用户

### TC-B04: 登录缺少 phone 字段 — 返回 400
- **类型**: 异常测试
- **关联验收标准**: 输入验证和错误处理

## D. 集成测试

### TC-D01: 注册 → 登录 → JWT 验证完整流程
- **类型**: 集成测试
- **关联验收标准**: 注册 + 登录完整链路
- **前置条件**: MongoDB 已启动，服务器运行中
- **输入**:
  - 注册：`{ "phone": "13800138020", "password": "Flow@2024", "nickname": "集成测试" }`
  - 登录：`{ "phone": "13800138020", "password": "Flow@2024" }`
- **执行步骤**:
  1. 发送注册请求，验证返回 201
  2. 发送登录请求，验证返回 200
  3. 检查登录返回的 token 字段存在且非空
- **预期输出**:
  - 注册 201 → 登录 200
  - 登录返回的 token 可用于后续请求（Task 2.2 完成后验证）
  - 数据库中该用户的 `passwordHash` 为 bcrypt 格式
- **清理**: 删除该用户

### TC-D02: 注册后 passwordHash 不以明文存储
- **类型**: 集成测试
- **关联验收标准**: 密码使用 bcrypt 加密存储
- **前置条件**: 已注册一个用户
- **输入**:
  - 查询 `db.users.find({phone: "13800138020"})`
- **执行步骤**:
  1. 注册一个新用户
  2. 直接查询 MongoDB users collection
  3. 检查 `passwordHash` 字段
- **预期输出**:
  - `passwordHash` 以 `$2b$` 开头（bcrypt 算法标识）
  - 数据库中**不存在**明文密码字段
- **清理**: 删除该用户

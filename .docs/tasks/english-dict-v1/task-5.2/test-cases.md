## 子任务 SUB-5.2.1: 今日一词推荐服务

### TC-001: 获取今日一词 — 正常返回
- **类型**: 功能测试
- **关联验收标准**: AC-1（GET /api/daily-word — 返回今日推荐单词）
- **前置条件**:
  - 数据库中存在至少 1 个单词
  - 无需登录（公开接口）
- **输入**:
  - `GET /api/v1/daily-word`
- **执行步骤**:
  1. 发起 GET 请求
  2. 检查响应体结构
- **预期输出**:
  - HTTP 状态码：200
  - 响应体包含：`{ word: { id, word, phonetic, coreMeaning, coreImageType, coreImageDescription }, date: "<YYYY-MM-DD>" }`
  - 若用户已登录，响应体可选包含 `isPinned: boolean`（是否为管理员置顶）
- **清理**: 无

### TC-002: 今日一词 — 同一天内返回相同单词
- **类型**: 功能测试
- **关联验收标准**: AC-1（一天内同一单词不变）
- **前置条件**:
  - 数据库中存在多个单词
  - 当天未设置置顶
- **输入**:
  - 连续两次 `GET /api/v1/daily-word`（间隔 < 1 分钟）
- **执行步骤**:
  1. 第一次请求，记录返回的 `word.id`
  2. 第二次请求，比较返回的 `word.id`
- **预期输出**:
  - 两次返回的 `word.id` 相同
  - 响应体 `date` 字段为当天日期
- **清理**: 无

### TC-003: 今日一词 — 跨天切换不同单词
- **类型**: 边界测试
- **关联验收标准**: AC-2（避免短期内重复）
- **前置条件**:
  - 数据库中单词数量 ≥ 3
  - 可模拟或修改系统日期，或查询缓存键确认过期逻辑
- **输入**:
  - 当天 `GET /api/v1/daily-word` 获取 wordId_A
  - 模拟进入下一天，再次请求
- **执行步骤**:
  1. Day 1: 请求获取 wordId_A
  2. 通过测试工具清理当日缓存（或等待日期自然变更），模拟 Day 2
  3. Day 2: 再次请求获取 wordId_B
- **预期输出**:
  - Day 1 和 Day 2 返回的单词不同（在单词数充足时大概率不同）
  - 推荐算法优先选择近期未被推荐过的单词
- **清理**: 恢复系统日期（若修改）

### TC-004: 今日一词 — 已登录用户优先推荐未学单词
- **类型**: 功能测试
- **关联验收标准**: AC-2（优先从未学单词中选）
- **前置条件**:
  - 数据库中有 5 个单词：A、B、C、D、E
  - 用户已登录，已学过单词 A、B、C（存在 LearningRecord）
  - 单词 D、E 未被该用户学习
- **输入**:
  - `GET /api/v1/daily-word`
  - Headers: `Authorization: Bearer <valid_token>`
- **执行步骤**:
  1. 以已登录用户身份发起请求
  2. 检查返回的单词
- **预期输出**:
  - HTTP 状态码：200
  - 返回的单词为 D 或 E（未学单词之一）
  - 不会返回已学单词 A、B、C
- **清理**: 无

### TC-005: 今日一词 — 所有单词均已学过时仍返回单词
- **类型**: 边界测试
- **关联验收标准**: AC-2（兜底策略）
- **前置条件**:
  - 数据库中有 2 个单词
  - 用户已登录，已学过全部 2 个单词
- **输入**:
  - `GET /api/v1/daily-word`
  - Headers: `Authorization: Bearer <valid_token>`
- **执行步骤**:
  1. 发起请求
- **预期输出**:
  - HTTP 状态码：200
  - 仍然返回一个单词（兜底：从已学单词中选择推荐历史中最久远或随机一个）
  - 不应返回 404 或空响应
- **清理**: 无

### TC-006: 今日一词 — 数据库无单词时返回空
- **类型**: 边界测试
- **关联验收标准**: AC-1
- **前置条件**:
  - 数据库中单词数为 0
- **输入**:
  - `GET /api/v1/daily-word`
- **执行步骤**:
  1. 发起请求
- **预期输出**:
  - HTTP 状态码：200
  - 响应体：`{ word: null, date: "<YYYY-MM-DD>", message: "暂无单词" }`
  - 或 HTTP 状态码：404，含提示信息
- **清理**: 恢复测试数据

### TC-007: 置顶今日一词 — 管理员设置指定单词
- **类型**: 功能测试
- **关联验收标准**: AC-3（支持管理员手动设置今日一词）
- **前置条件**:
  - 管理员已登录，token 有效
  - 目标单词存在于数据库中（wordId: `<valid_id>`）
- **输入**:
  - `POST /api/v1/daily-word/pin`
  - Headers: `Authorization: Bearer <admin_token>`
  - Body: `{ wordId: "<valid_id>" }`
- **执行步骤**:
  1. 以管理员身份发起 POST 请求
  2. 随后 `GET /api/v1/daily-word` 验证
- **预期输出**:
  - POST 响应 HTTP 状态码：200
  - POST 响应体：`{ success: true, wordId: "<valid_id>", pinnedAt: "<ISO时间>" }`
  - GET daily-word 返回的单词为被置顶的单词
  - GET daily-word 响应体含 `isPinned: true`
- **清理**: 清除置顶设置

### TC-008: 置顶今日一词 — 非管理员被拒绝
- **类型**: 异常测试
- **关联验收标准**: AC-3（仅管理员可操作）
- **前置条件**:
  - 普通用户已登录，token 有效
- **输入**:
  - `POST /api/v1/daily-word/pin`
  - Headers: `Authorization: Bearer <user_token>`
  - Body: `{ wordId: "<valid_id>" }`
- **执行步骤**:

- **预期输出**:
  - HTTP 状态码：403
  - 响应体含 `{ error: { code: "FORBIDDEN", message: "权限不足，需要管理员权限" } }`
- **清理**: 无

### TC-009: 置顶今日一词 — 未登录被拒绝
- **类型**: 异常测试
- **关联验收标准**: AC-3
- **前置条件**: 无
- **输入**:
  - `POST /api/v1/daily-word/pin`
  - 无 Authorization header
  - Body: `{ wordId: "<valid_id>" }`
- **执行步骤**:
  1. 不带 token 发起请求
- **预期输出**:
  - HTTP 状态码：401
  - 响应体含 error 信息
- **清理**: 无

### TC-010: 置顶今日一词 — 单词不存在
- **类型**: 异常测试
- **关联验收标准**: AC-3
- **前置条件**:
  - 管理员已登录
- **输入**:
  - `POST /api/v1/daily-word/pin`
  - Body: `{ wordId: "60f7c1a2b3c4d5e6f7a8b9c0" }`（不存在的 ID）
- **执行步骤**:
  1. 以管理员身份发起请求
- **预期输出**:
  - HTTP 状态码：404
  - 响应体含 `{ error: { code: "NOT_FOUND", message: "单词不存在" } }`
- **清理**: 无

### TC-011: 置顶今日一词 — 置顶跨天后失效
- **类型**: 边界测试
- **关联验收标准**: AC-1（置顶仅当天有效）
- **前置条件**:
  - 管理员已置顶单词 A
  - 当天 `GET /api/v1/daily-word` 返回单词 A
- **输入**:
  - 模拟进入下一天后 `GET /api/v1/daily-word`
- **执行步骤**:
  1. Day 1: 管理员置顶单词 A
  2. Day 1: 验证 daily-word 返回 A
  3. 清理缓存或模拟 Day 2
  4. Day 2: 再次请求 daily-word
- **预期输出**:
  - Day 2 返回的单词由推荐算法决定（不再强制为 A）
  - 若推荐算法恰好再次选中 A 则不构成 Bug（概率性）
- **清理**: 无

### TC-012: 推荐历史记录 — 避免短期内重复推荐
- **类型**: 功能测试
- **关联验收标准**: AC-2（记录已推荐历史避免短期内重复）
- **前置条件**:
  - 数据库中有 5 个单词 A、B、C、D、E
  - 无用户登录（匿名模式）
- **输入**:
  - 连续 5 天每天请求一次（模拟或逐日推进）
- **执行步骤**:
  1. Day 1–5: 每天请求一次 daily-word，记录返回的 wordId
  2. 检查是否有重复
- **预期输出**:
  - 5 天内 5 个单词全部出现过一次（无重复，覆盖所有单词后才循环）
  - 或最多重复 1 次（取决于推荐策略的具体实现：如优先队列 + 冷却窗口）
- **清理**: 清除推荐历史

  2. 验证响应体各字段

      "wordbankCount": 3,
      "wordCount": 50,
      "userCount": 10,

        { "date": "2026-07-04", "count": 8 },

### TC-017: Dashboard 趋势数据 — 7 天日期范围准确
- **类型**: 功能测试
- **关联验收标准**: AC-4（最近 7 天新增趋势）

- **预期输出**:

  - 每天的 count 与预期一致（如 yesterday: 5, today: 3）
  - 8 天前的数据不计入 7 天窗口
  - 日期格式为 `YYYY-MM-DD`，按日期升序排列
- **清理**: 无

## 子任务 SUB-5.2.3: 前端集成

### TC-019: 前端首页 — 今日一词从 API 获取
- **类型**: 集成测试
- **关联验收标准**: AC-5（前端首页今日一词调用 GET /api/daily-word）
- **前置条件**:
  - 后端服务正常运行
  - 数据库中有单词
  - 用户打开首页
- **输入**:
  - 访问首页 `/pages/home/index`
- **执行步骤**:
  1. 打开首页
  2. 检查网络请求
  3. 观察「今日一词」卡片内容
- **预期输出**:
  - 发起 `GET /api/v1/daily-word` 请求
  - 不再使用 `Math.floor(Date.now() / 86400000) % words.length` 伪随机逻辑
  - 卡片正确展示 API 返回的单词信息（word、phonetic、coreMeaning 等）
- **清理**: 无

### TC-020: 前端首页 — 今日一词 API 失败时的降级处理
- **类型**: 异常测试
- **关联验收标准**: AC-5
- **前置条件**:
  - 后端 `GET /api/v1/daily-word` 返回 500 或网络不通
- **输入**:
  - 访问首页
- **执行步骤**:
  1. 模拟 API 故障
  2. 打开首页
- **预期输出**:
  - 今日一词卡片不显示或显示占位提示（如"暂无推荐"）
  - 其余页面内容（搜索、全部词汇列表）不受影响
  - 不出现白屏或崩溃
- **清理**: 恢复 API

# 测试用例 — Task 6.1: 缓存与搜索优化

## 测试范围概览

| 维度 | 说明 |
|------|------|
| 功能测试 | 验证缓存命中/未命中、缓存失效、搜索排序 |
| 边界测试 | 缓存 TTL 过期边界、空结果、极值分页参数 |
| 异常测试 | 缓存服务不可用降级、无效参数 |
| 集成测试 | 数据变更链路（写操作 → 失效 → 读缓存） |

## SUB-6.1.1: API 响应缓存

### TC-001: 今日一词 — 首次请求缓存未命中
- **类型**: 功能测试
- **关联验收标准**: 今日一词缓存（按天）
- **前置条件**: 缓存层已启动，数据库中存在当日有效 DailyWord 记录
- **输入**:
  - GET `/api/v1/daily-word`
- **执行步骤**:
  1. 清除缓存中该 key
  2. 发送 GET `/api/v1/daily-word` 请求
  3. 检查响应头或日志，确认缓存未命中（cache miss）
  4. 检查响应体包含有效的今日一词数据
- **预期输出**:
  - HTTP 状态码：200
  - 响应体包含 `word`、`wordId`、`reason` 等字段
  - 日志/调试信息显示 cache miss
- **清理**: 无

### TC-002: 今日一词 — 第二次请求缓存命中
- **类型**: 功能测试
- **关联验收标准**: 今日一词缓存（按天）
- **前置条件**: TC-001 已执行，缓存中已有当日数据
- **输入**:
  - GET `/api/v1/daily-word`
- **执行步骤**:
  1. 发送 GET `/api/v1/daily-word` 请求
  2. 检查响应头或日志，确认缓存命中（cache hit）
  3. 比较本次响应体与首次请求一致
- **预期输出**:
  - HTTP 状态码：200
  - 响应体与首次请求完全相同
  - 日志/调试信息显示 cache hit
- **清理**: 无

### TC-003: 今日一词 — 跨天自然过期
- **类型**: 边界测试
- **关联验收标准**: 今日一词缓存（按天）
- **前置条件**: 缓存中存在前一日的数据（TTL 设为"当天剩余秒数"）
- **输入**:
  - GET `/api/v1/daily-word`
- **执行步骤**:
  1. 手动设置缓存 key 的 TTL 为 1 秒，等待过期
  2. 发送 GET `/api/v1/daily-word` 请求
  3. 确认缓存未命中，数据库被查询
- **预期输出**:
  - HTTP 状态码：200
  - 日志/调试信息显示 cache miss，随后从数据库加载新数据
- **清理**: 无

### TC-004: 词库列表 — 首次请求缓存未命中
- **类型**: 功能测试
- **关联验收标准**: 词库列表缓存（TTL 5 分钟）
- **前置条件**: 数据库中存在至少 2 个公开词库
- **输入**:
  - GET `/api/v1/wordbanks`
- **执行步骤**:
  1. 清除缓存
  2. 发送请求
  3. 确认 cache miss，数据来自数据库
- **预期输出**:
  - HTTP 状态码：200
  - 响应体 `data` 数组长度 >= 2
  - cache miss
- **清理**: 无

### TC-005: 词库列表 — 缓存命中后不查数据库
- **类型**: 功能测试
- **关联验收标准**: 词库列表缓存（TTL 5 分钟）
- **前置条件**: 已缓存词库列表数据
- **输入**:
  - GET `/api/v1/wordbanks`
- **执行步骤**:
  1. 使用数据库 profiling/monitoring 或 mock 验证
  2. 连续发送 3 次请求
  3. 确认仅第 1 次触发数据库查询，后 2 次命中缓存
- **预期输出**:
  - 3 次请求均返回 200
  - 数据库查询次数 = 1
- **清理**: 无

### TC-006: 词库列表 — TTL 过期后重新加载
- **类型**: 边界测试
- **关联验收标准**: 词库列表缓存（TTL 5 分钟）
- **前置条件**: 缓存中存在词库列表数据
- **输入**:
  - GET `/api/v1/wordbanks`
- **执行步骤**:
  1. 将缓存 TTL 临时设为 2 秒（通过配置或测试手段）
  2. 等待 3 秒使缓存过期
  3. 发送请求，确认 cache miss 并从数据库重新加载
- **预期输出**:
  - HTTP 状态码：200
  - cache miss → 重新加载 → 新缓存
- **清理**: 恢复默认 TTL 配置

### TC-007: 单词详情 — 缓存命中
- **类型**: 功能测试
- **关联验收标准**: 单词详情缓存（TTL 10 分钟）
- **前置条件**: 数据库中存在单词 `id=abc123`，属于公开词库
- **输入**:
  - GET `/api/v1/words/abc123`
- **执行步骤**:
  1. 发送第 1 次请求，确认 cache miss
  2. 发送第 2 次请求，确认 cache hit
  3. 对比两次响应一致
- **预期输出**:
  - 两次均返回 200
  - 响应包含 `word`, `coreMeaning`, `physicalImageType`, `extendedMeanings` 等字段
  - 第 1 次 cache miss，第 2 次 cache hit
- **清理**: 无

### TC-008: 单词详情 — 不同单词各自缓存
- **类型**: 功能测试
- **关联验收标准**: 单词详情缓存（TTL 10 分钟）
- **前置条件**: 数据库中存在两个单词 A 和 B
- **输入**:
  - GET `/api/v1/words/A_id`
  - GET `/api/v1/words/B_id`
- **执行步骤**:
  1. 请求单词 A（cache miss）
  2. 请求单词 B（cache miss，不同 key）
  3. 再次请求单词 A（cache hit）
  4. 再次请求单词 B（cache hit）
- **预期输出**:
  - 4 次均返回 200
  - A 和 B 各自独立缓存，互不干扰
- **清理**: 无

### TC-009: 单词创建 — 触发缓存失效
- **类型**: 集成测试
- **关联验收标准**: 数据变更（词库/单词修改）时主动失效对应缓存
- **前置条件**: 管理员已登录，缓存中有词库 X 的单词列表
- **输入**:
  - POST `/api/v1/words` — `{ wordbankId: "X_id", word: "newword", ... }`
- **执行步骤**:
  1. 先 GET `/api/v1/wordbanks/X_id/words` 缓存单词列表
  2. POST 创建新单词到词库 X
  3. 再 GET `/api/v1/wordbanks/X_id/words`，确认能从数据库获取到包含新单词的列表（非旧缓存）
- **预期输出**:
  - POST 返回 201
  - 第 2 次 GET 返回的列表包含新创建的单词
  - 缓存失效生效
- **清理**: 删除测试单词

### TC-010: 单词更新 — 触发对应详情缓存失效
- **类型**: 集成测试
- **关联验收标准**: 数据变更时主动失效对应缓存
- **前置条件**: 管理员已登录，缓存中有单词 `id=abc123` 的详情
- **输入**:
  - PUT `/api/v1/words/abc123` — `{ coreMeaning: "已更新的核心释义" }`
- **执行步骤**:
  1. GET `/api/v1/words/abc123` 缓存原详情
  2. PUT 更新该单词
  3. GET `/api/v1/words/abc123`，确认返回更新后的数据（非旧缓存）
- **预期输出**:
  - PUT 返回 200，数据已更新
  - 第 2 次 GET 返回 `coreMeaning: "已更新的核心释义"`
- **清理**: 恢复原数据

### TC-011: 单词删除 — 触发缓存失效

### TC-012: 词库更新 — 触发词库列表缓存失效
- **类型**: 集成测试
- **关联验收标准**: 数据变更时主动失效对应缓存

### TC-013: 缓存不可用 — 自动降级到数据库
- **类型**: 异常测试
- **关联验收标准**: 缓存策略：内存缓存或 Redis（可选），合理设置 TTL
- **前置条件**: 缓存层可模拟故障（如 Redis 连接断开，或内存缓存模块抛出异常）
- **输入**:
  - GET `/api/v1/wordbanks`
- **执行步骤**:
  1. 模拟缓存服务不可用（断连 / 异常）
  2. 发送请求
  3. 确认仍返回正确数据（直接查数据库）
- **预期输出**:
  - HTTP 状态码：200
  - 响应数据正确
  - 不应返回 5xx 错误
- **清理**: 恢复缓存服务

### TC-014: 缓存可配置 — 禁用缓存后不命中
- **类型**: 功能测试
- **关联验收标准**: 缓存可配置（是否启用、TTL 时长）
- **前置条件**: 配置 `CACHE_ENABLED=false`（或等价配置）
- **输入**:
  - GET `/api/v1/wordbanks`（两次连续请求）
- **执行步骤**:
  1. 确认缓存已配置为禁用
  2. 连续发送两次 GET `/api/v1/wordbanks`
  3. 确认两次都走了数据库（cache miss）
- **预期输出**:
  - 两次均返回 200
  - 两次均查询数据库，无缓存写入
- **清理**: 恢复 `CACHE_ENABLED=true`

### TC-015: 缓存可配置 — 自定义 TTL
- **类型**: 功能测试
- **关联验收标准**: 缓存可配置（是否启用、TTL 时长）
- **前置条件**: 配置 `CACHE_TTL_WORDBANK_LIST=60`（60 秒，非默认 300 秒）
- **输入**:
  - 多次 GET `/api/v1/wordbanks`
- **执行步骤**:
  1. 设置 TTL=60s
  2. 第 1 次请求 → cache miss
  3. 30 秒后第 2 次请求 → cache hit
  4. 等待 70 秒后第 3 次请求 → cache miss（已过期）
- **预期输出**:
  - 第 1 次 cache miss
  - 第 2 次 cache hit
  - 第 3 次 cache miss
- **清理**: 恢复默认 TTL

## SUB-6.1.2: 搜索性能优化

### TC-016: 单词名索引 — EXPLAIN 验证
- **类型**: 功能测试
- **关联验收标准**: words.name 建立索引；EXPLAIN 验证索引使用
- **前置条件**: 数据库中有大量单词（>= 100 条）
- **输入**:
  - 数据库查询 `db.words.find({ word: /^test/ })` 的 EXPLAIN 输出
- **执行步骤**:
  1. 在 MongoDB 中执行 `db.words.find({ word: /^prefix/ }).explain("executionStats")`
  2. 检查 `winningPlan.inputStage.stage`
  3. 确认使用了 `IXSCAN`（索引扫描）而非 `COLLSCAN`（全表扫描）
- **预期输出**:
  - `winningPlan.inputStage.stage` = `"IXSCAN"`
  - `executionStats.totalDocsExamined` 接近于返回文档数（非全表文档数）
- **清理**: 无

### TC-017: 单词搜索 — 索引加速对比
- **类型**: 功能测试
- **关联验收标准**: EXPLAIN 验证索引使用
- **前置条件**: 数据库中 >= 1000 条单词
- **输入**:
  - API: GET `/api/v1/words?q=app`
- **执行步骤**:
  1. 确认 `word` 字段索引存在
  2. 发送搜索请求
  3. 检查 API 响应时间 < 100ms（在合理硬件下）
  4. 通过 EXPLAIN 确认查询计划使用了索引
- **预期输出**:
  - HTTP 状态码：200
  - 响应时间显著低于无索引时的全表扫描
  - 查询计划使用 IXSCAN
- **清理**: 无

### TC-018: 搜索排序 — 前缀匹配优先于中间匹配
- **类型**: 功能测试
- **关联验收标准**: 搜索结果按相关度排序（前缀匹配优先于中间匹配）
- **前置条件**: 数据库中存在以下单词：`apple`, `pineapple`, `application`, `crabapple`
- **输入**:
  - GET `/api/v1/words?q=app`
- **执行步骤**:
  1. 发送搜索请求 `?q=app`
  2. 检查返回的 `data` 数组顺序
  3. `apple`、`application`（前缀匹配 → 以 "app" 开头）应排在 `pineapple`、`crabapple`（中间匹配 → 包含 "app" 但非前缀）前面
- **预期输出**:
  - HTTP 状态码：200
  - 结果排序：前缀匹配的单词在前，中间匹配的单词在后
  - 同类（同为前缀匹配或同为中间匹配）内部可按字母序或其他合理规则排列
- **清理**: 无

### TC-019: 搜索 — 精确匹配排最前

- **关联验收标准**: 搜索结果按相关度排序（前缀匹配优先于中间匹配）
